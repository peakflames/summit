## 1. Client-only architecture, no backend

**Decision:** Summit has no server or API — it is a Vite + TypeScript SPA that persists all
state to the browser's `localStorage`.

**Rationale:** This is a public reference example for the `peak-workflow` plugin. Favoring a
client-only architecture keeps the end-to-end lifecycle walkthrough focused on clarity rather
than backend/infra complexity.

## 2. Version sourced from package.json, stamped at both footer and console startup

**Decision:** `package.json`'s `version` field is the single source of truth for the app
version. It is injected as a build-time constant (via a Vite `define`) and used both for the
footer display and a `console.info` log on app startup.

**Rationale:** Keeps version exposure and startup logging in sync with a single authoritative
value, avoiding drift between what's displayed and what's built.
